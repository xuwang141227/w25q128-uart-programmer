# 设计与上板注意事项

## 原厂依据

本设计使用已读取的 **Winbond W25Q128JV Revision C，2016-11-16**
标准 JV 手册，而不是把 W25Q128JV-DTR 的典型时间当作普通 JV 参数。
读取的原厂 PDF 镜像路径为
`firefly/thirdparty-datasheets/storage/w25q128jv.pdf`，
Git blob 为 `9f622e6d3a1189fe872c812a512c2bbdb178c894`。

| 章节 / 手册印刷页 | 使用的规则 |
|---|---|
| 7.1.1 / 7.1.2 | SR1 bit 0 为 BUSY，bit 1 为 WEL；擦写结束后 WEL 清零 |
| 8.2.6 | `03h` 普通读，24 位地址，无 dummy 周期，BUSY 时不能直接读 |
| 8.2.13 | `02h` 页编程，1..256 字节；完整页地址低 8 位为零，跨页会回卷 |
| 8.2.15 | `20h` 擦除地址所在的 4 KiB sector，每次之前都需要 WREN |
| 9.3 / p.59 | `tVSL >= 20 us`，写指令前 `tPUW >= 5 ms` |
| 9.6 / p.62 | `03h` 最高 50 MHz；读 CS 高电平至少 10 ns，擦写至少 50 ns |
| 9.6 / p.63 | `tPP` 典型 0.7 ms、最大 3 ms；`tSE` 典型 45 ms、最大 400 ms |

时间上限不是固定延时：RTL 根据 BUSY 判断完成，用大于手册最大时间的
10 ms / 600 ms 作为故障保护。状态轮询间隔为 5000 个主时钟，
即 100 us，另加状态命令本身的开销。每个 sector 独立获得 600 ms 预算。

WEL 检查可识别未执行 WREN、部分拒绝命令和异常连接，但 SR1 没有
“所有存储单元都写对”的通用保证。因此成功 ACK 表示 Flash 已就绪并完成
协议层操作；实际数据正确性由 Python 每页读回比较保证。
对擦除结果不额外逐字节 blank-check，不自动清除原有保护配置。

## 状态与数据通路

接收器对 UART RX 双级同步，在半个起始位检查电平，然后每一位中心采样。
50 MHz 对 19200 的分频为 2604 个时钟，实际约 19201.23 baud，
误差约 +0.0064%。停止位错误不产生有效数据。

顶层先完整接收 E3 的 256 字节，再启动页编程；256 字节页缓存也用于读回。
只有单条命令在途，因此读写缓存不会同时被两个事务占用。
写入位置每页增加 256，即使最后一页实际只有少量有效数据；
最后一页 ACK 按 E1 的有效字节长度计算。
擦除只计算 `ceil(length/4096)`，不擦除这个范围外的 sector。

SPI 分为字节移位器与 Flash 事务控制器。所有状态机只使用主时钟，
不以 `spi_clk` 作为内部逻辑时钟。SPI 在字节内部连续产生 40 ns 高、
40 ns 低的时钟，相邻字节之间允许额外低电平间隔；
12.5 Mbps 指 SPI 位时钟速率，不代表扣除命令/字节间隔后的持续有效吞吐率。
CS 在整条 SPI 命令（含地址和数据）期间保持低，命令间明确留出高电平时间。

接收字段的**字节间**超时为 100 ms，而非整包 100 ms；
19200 下 256 字节本身约需 133 ms，不会被误判超时。
超时后返回 F4，重新寻找命令头。处于擦写或应答状态时不接受新命令；
主机必须等待应答完全接收，不能在 FPGA 忙时提前塞入数据。

复位清除长度、模式与烧写进度，`reboot_n=1`、CS=1、SPI CLK=0、UART TX=1。
镜像烧写状态不跨复位保留。E4 将 reboot_n 保持低而非产生窄脉冲；
如果板卡重启电路需要脉冲宽度或开漏输出，应在板级 wrapper 中实现。

## 板卡连接和边界

- 使用 50 MHz 时钟。顶层参数中的 `CLK_HZ` / `BAUD` 用于 UART 分频；
  SPI 和以周期指定的超时均以 50 MHz 为前提，不是任意时钟的自动配置。
- 输入为 TTL/CMOS 串口，**不是 RS-232 正负电压接口**；USB-UART 与 FPGA
  共地，并按器件允许的 I/O 电压连接。Flash 供电按具体完整料号手册选择。
- Flash `/WP`、`/HOLD`（以及封装有独立 `/RESET` 时）须处于正常非激活状态；
  CS 外部上拉，保证 FPGA 配置前和电源爬升时 Flash 不被误选中。
- FPGA 的 `reset_n` 释放必须满足时钟域要求，建议板级采用异步置位、
  同步释放的复位电路；10 ms 保护从复位释放计时，复位应覆盖 Flash 供电稳定前。
- 必须核对完整订购料号/封装对应的引脚与复用功能，不能仅按“JVEM”后缀猜引脚。
  以实际购买批次的最新原厂手册为准。
- 假定 Flash 处于上电标准 SPI、未进入 deep power-down 或 QPI，
  没有正在挂起的擦写，没有写保护或 sector lock。
  本实现不自动解锁、修改状态寄存器或退出其他主机留下的特殊工作模式。
- 如果是 FPGA 配置 Flash，烧写时必须正确仲裁配置控制器/JTAG/其他主机的总线所有权。
  不能让两个主机同时驱动 Flash；重启方式由具体 FPGA 和板级电路决定。
- 超时不保证 Flash 已停止内部擦写；返回 F4 后主机必须停止烧写。
  不要在仍 BUSY 时掉电或复位去“恢复”写操作，先按器件手册处理异常。

目标工程至少需要 20 ns 的主时钟约束：

```tcl
create_clock -name clk_50m -period 20.000 [get_ports clk]
```

还需要由目标 FPGA 工具和板级走线确定 GPIO 管脚、I/O 标准、
UART 异步输入路径、复位路径和 SPI 输入/输出时序约束。
没有具体器件和走线数据时不能提供可信的通用全套约束；
必须在真实目标上完成布局布线和静态时序检查。

## 行为模型范围

Flash 模型默认模拟 64 KiB，足以覆盖跨 sector 测试；实际 RTL 支持完整 16 MiB。
模型初值刻意为 `00` 而不是 `FF`，用于检查擦除范围与真正的 NOR 编程：
不擦除直接写无法使 `0` 变回 `1`。
擦写内容在模型接受命令时更新，BUSY 延迟结束前不允许读或新擦写，
因此可检查访问顺序，但不声称模拟了掉电时存储单元的最终状态。
`stall_completion` 模拟已接受操作后 BUSY 不退出；
`force_busy` 模拟命令前 Flash 一直忙；`reject_wren` 模拟写使能失败。

常规 TB 将 Flash 擦写时间缩短以减少仿真耗时；独立 `tb_flash_limits`
使用真实 3 ms / 400 ms 操作时长验证默认超时，不能只凭加速模型说明
手册最大值已被覆盖。Python 单元测试为传输协议测试，不等同于真实串口硬件测试。
